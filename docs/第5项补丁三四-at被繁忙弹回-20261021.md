# 第 5 项补丁三/四：@ 被「繁忙」连环弹回（2026-10-21 12:53–12:57）

## 现象

补丁二把积压队列的 drain 修好后，@ 仍然不回。日志里同一条 seq 反复出入队：

```
12:47:28 会话繁忙，暂存唤醒原因 group:906710082（atMention@seq1962，队列 20 条）
12:49:37 补发繁忙期间积压的唤醒：atMention@seq1962（队列剩 19 条）
12:49:37 会话繁忙，暂存唤醒原因 group:906710082（atMention@seq1962，队列 20 条）  ← 又塞回去
```

## 根因：三处「忙就入队」把关

`isConversationBusyV2()` 包含 `pendingWakeTimer` / `pendingWakeKeys` / `promptQueues` /
`v2TurnStartAt` / `collectors`，群聊热闹时几乎恒为真。同一份「忙」判定被套在三个地方：

1. `scheduleWakeV2()` —— 排唤醒时
2. `sendWakePromptV2()` —— 真正投递时
3. `drainPendingWakeFor()` —— 补发时（已在补丁二加 `ignoreBusy`）

只放开第 3 处，前两处照样把 @ 弹回队列，形成「取出→塞回」死循环。

## 改动

- `scheduleWakeV2(key, reason, opts)`：高优先级（`private`/`atMention`/`question`）跳过着队，
  照常排定时器。
- `drainPendingWakeFor` 调用时带 `{ force: true }`。
- `sendWakePromptV2`：高优先级跳过着队，直接排队投递（`deliverPrompt` 按会话串行）。
- 唤醒文案补两个专用分支：`atMention` 明确写「有人在群里 @ 了你 —— 明确点名找你，不是路过的话题」，
  `private` 写「私聊就是明确找你，直接回」。原来这两种走默认分支，模型只看到「原因：atMention」。

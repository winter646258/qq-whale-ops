### 2.2 三个「假修好」

值得单独记，因为它们都被误判过：

**① 群生图「授权了但画不出来」** —— `imageSceneFor` 判定「这个群最近有没有主人说话」，读的是 `social.recentMessages`（一代）。二代模式下消息存在 `socialV2.conversations.get(key).recentMessages`（见 `bridge.js:8772` 注释原文）。所以二代下 `ownerSpoke` 恒 false，连画画提示都不给她。她是诚实地回「权限得你在后台开」。

**② 群里 `owner-group` 只活 4 秒** —— trae 回一句就 `turn/end`，她收尾阶段想画时额度已收回。加了 90 秒宽限。

**③ 后台提醒把唤醒原因洗成空串** —— `notify-ai`（`bridge.js:4638`）走 `deliverPrompt(key, promptText, { silent: true })`，**没带 `wakeReason`**；而 `deliverPromptNow` 一上来就 `globalThis.__qqTurnContext = { key, reason: opts.wakeReason || '' }`。紧跟着的真唤醒（`reason=question`）被覆盖。所以宽限分支判 `byMention` 时拿到的是空串。

### 2.3 关于「管理命令仅管理员可用」

**不是她的判断，是桥接嵌死的。** 原文（`bridge.js:11532` 附近，已改）：

```js

  if (!isOwner) {
    await sendToQQ(key, '管理命令仅管理员可用。');
```

## 5. 下一阶段：设计任务书（给 Codex）

主人原话（`m01495`）：「下一个阶段的目标是实现不同对话间的互通，在于管理员的私聊中有群聊和其他人之间的聊天记忆，并且实现在群里受委屈了还能回来报告管理员主动与管理员对话的功能」

追加（`m01559`）：「受委屈主动报告不止委屈，高兴，有趣的事情也可以」

### 5.1 目标 A：跨会话记忆互通

**问题**：`private:1124721191` 和 `group:906710082` 是两套独立的 `socialV2` 会话，各有自己的 `recentMessages` / `unread` / `agentToken`。她在群里经历的事，私聊里不知道；私聊里说过的话，群里也想不起来。

**设计要求**：

1. **三层结构**，不要一把梭全共享：
   - **共享层** `state/shared-memory.json` —— 她与你（主人）之间的约定、群里的大事、跨场景的事实。两边都注入。
   - **私聊专属** —— 只属于你和她的东西（语气、称呼、承诺、情绪债）。群里不出现。
   - **群聊专属** —— 群友印象、群内梗。私聊里**只在她主动提及时**才带。
2. **注入要按「谁在看」过滤**。同一份共享层，私聊里可以说「上次你在群里说的那句话」，群里就说不出口。
3. **容量要封顶**。现在 `contextWindow: 20`。共享层条目建议 ≤ 30 条 + 每条 ≤ 80 字，超出按「最近提到」淘汰。
4. **反例**：不要做成「把所有群聊复制一份到私聊」。那会把私聊变成聊天记录回放，也烧 token。

**建议切入点**：
- 存储：仿 `mood-store.js` 的写法（纯逻辑 ESM + 独立单测），新增 `src/shared-memory-store.js`
- 注入点：`bridge.js:10956` 那行 `const base = roleLine + tokenLine + ...`，加一个 `sharedLine`
- 工具：`qq_shared_memory` 四 action（read / remember / forget / list），走 `mcp-snowluma-safe.js` 的 `TOOL_CONFIG_FLAGS`

### 5.2 目标 B：主动报告（不只是委屈）

**问题**：她现在只能被动等你。要让她能在群里受了委屈 / 遇上高兴事 / 发现有趣的东西时，**主动**来找你。

**设计要求**：

1. **触发来源必须是她的判断，不是关键词表**。她自己调工具「决定要不要跟你说」，不要在桥接里写正则匹配「委屈」两个字。
2. **情绪必须分正向和负向，不能只有「受委屈」**：
   - 负向：被冤枉、被骂、被冷落、群里吵架、被忽视
   - 正向：被夸、群友送礼物、聊到开心的事、有人记得她
   - 中性有趣：群里出现好玩的事、发现了新梗
   - 现有的 `qq_mood` 有 `vent`（暗流，只记负向）和 `affinity`（好感度）。**需要扩展**：加 `share`（想说的好事）和 `highlight`（有趣片段），或者用一个 `signal` action 带 `valence`（-1..+1）。
3. **必须节流**。硬约束：`private:<ownerQQ>` 的主动唤醒 **6 小时内最多 1 次**，且**必须是别的群聊天闹起来的**（不能她自己在私聊里反复刷）。同一件事不许重复报告（用事件 id 去重）。
4. **通道要安全**。现有 `deliverPrompt(key, promptText, { silent: true, wakeReason: ... })` 可以直接用，但**必须带 `wakeReason`** —— 今天的 bug ③ 就是没带，把上下文洗成空串了。建议 `wakeReason: 'share'`。
5. **不能变成骚扰**。如果主人 3 次没回，下次报告自动降频一半；如果连续 3 天主人一次没回，暂停一周。
6. **她要能说「不打扰」**。加一个 `qq_set_report_policy`（enabled / quiet hours / 上限），让她自己调，也让你能看。

**建议切入点**：
- `mood-store.js` 扩展：`undercurrent` 已经有 `weight`，可以复用为「情绪强度」；新增 `signals[]` 数组存「想告诉主人的事」
- 主动唤醒：仿 `social.loopTimer`（`bridge.js:10014`，5 秒一次 `socialLoopTick`），但**不要**加新的 `setInterval`（云上只有 568MB 可用，已挂 6 个）
- 独立触发：在 `socialLoopTick` 里顺带判（同一 tick 内多干一件事，零额外开销）

## 7. 坑与教训（血泪版）

1. **`systemctl is-active` 查不出「进程活着、内部服务死了」。** 10-22 18:32 装插件把 DSH 打挂 83 分钟，`is-active` 全程 active、`NRestarts=0`，但群里每 3 秒刷一条 `sessionController is unavailable`，累计 1660 条。判断 DSH 死活要看 `/var/log/dsh-web.log` 和实际能不能发消息。
2. **带 bundle 的插件要当上线操作对待。** 装完不重启 ≠ 不生效，下一次重启才炸。
3. **`node --check` 通过 ≠ 作用域正确。** 今天两次：`let turnContext` 插到了另一个闭包（22 条 `turnContext is not defined`）；补丁缩进写错（命中 0 次，白跑）。

5. **线上和仓库不同步。** 本地 `scripts/switch-provider.sh` 曾是连 `probe_primary` 都没有的旧版，从线上 scp 回来才对。
6. **「已上线」≠「跑通过」。** 搜索 MCP 上线至今调用 **0 次**，因为工具描述写成了「只用于理解词义」—— 模型看着觉得「这不归我管」。

8. **`/api/socialV2/mood` 的 read 必须带 key**（`?token=$T&key=private:1124721191&action=read`），只带 token 会报 `key 不能为空`。

所以下一阶段做跨会话记忆和主动报告时，记住：**决定权要留在她手里**。桥接负责提供信息、执行动作、兜底安全，但「要不要说」「说什么」「跟谁说」得是她的判断。

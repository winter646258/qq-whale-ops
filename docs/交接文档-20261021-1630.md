## 4. 今天踩的坑（按痛感排序）

### 4.1 改文件 ≠ 改进程 ★★★★★

`qq-provider-switch` 是 08:41 起的**长驻 bash 循环**，`A_PROVIDER`/`B_PROVIDER`
在脚本第 55/56 行启动时就进了内存。我改完文件、重启桥接、验证 loomy 一切正常，
60 秒后它按**旧值**（buddy/trae）判定"loomy 不在配对内"，直接 `set_provider buddy`
把桥接重启回坏渠道。

**教训**：改守护脚本的常量后必须 `systemctl restart qq-provider-switch`，
且顺序是「停守护 → 改配置 → 重启桥接 → 启守护」。

### 4.2 误把 /bin/bash 当脚本备份了 8 次 ★★★★

`systemctl cat | grep -oE 'ExecStart=[^ ]+'` 抓到的是 `ExecStart=/bin/bash`，
于是 `cp -a /bin/bash /bin/bash.bak-*` 在 `/bin` 里堆了 8 份 bash 副本。
后来 `python3` 读"脚本"报 `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xf0`
才暴露。

**教训**：从 ExecStart 里要挑 `.sh` 结尾的那个 token；改文件前先 `file` 一下确认是文本。

### 4.3 假探测比没探测更坏 ★★★★

`probe_buddy()` 只 `curl http://127.0.0.1:3100/api/dsh/model` 看本地控制台能不能报出模型。
buddy 坏了一整天，它每次都判"已恢复"，切回去立刻又失败（09:02:11 → 09:02:14）。

**教训**：健康检查必须打到**真正会坏的那一层**。

### 4.4 TDZ：`main()` 里靠后的 const 在早期初始化路径上不可用 ★★★

`loadSocialV2State()` 初始化时会调 `saveSocialV2State()`，我在 save 里用了
`const PENDING_WAKE_MAX`，那时还没初始化 →
`读取 socialV2 状态失败: Cannot access 'WAKE_PRIORITY' before initialization`。
**这个 bug 会让整份会话状态读不出来**，比功能失效严重得多。
修法：save/load 用字面量，优先级"用时才算"。

### 4.5 唤醒原因写成英文枚举值，模型看不懂 ★★★

`atMention` 走默认分支，她收到的提示词是 `原因：atMention`——没有一句说"有人点名 @ 你"。
所以她按"路过的群话题"处理，判断完继续潜水。补了专用文案才好。

**教训**：给模型的提示词里不要出现内部枚举名，要写人话。

### 4.6 断言期望值不能来自我的推测 ★★

第 7 项测试我断言历史案例应解析到 `mfuns-11`，实测是 `mfuns-05`——因为
`mfuns-05` 的 desc **恰好就是**"你这吃白饭的蓝色大肥鱼"（`mfuns-11` 的 desc 是
"我是吃白饭的大肥鱼"，她当时是搜关键词找到的）。改成校验「命中项 desc 与输入完全一致」。

## 5. 操作手册

### 5.1 连服务器（有坑，必须照做）

```powershell
# 必须用 Windows 自带 OpenSSH。Git 自带的会崩：
#   fatal error - couldn't create signal pipe, Win32 error 5
& "C:\Windows\System32\OpenSSH\ssh.exe" alihz "命令"
& "C:\Windows\System32\OpenSSH\scp.exe" 本地文件 alihz:/tmp/
```

- SSH 会随机 `Connection timed out`，**重试 3~4 次**，不要判服务器故障。
- PowerShell 会先把 `$(...)`、`require(` 本地展开，**复杂远程脚本一律写成 .sh 文件 scp 上去执行**。

### 5.2 改 bridge.js 的标准流程

```bash
# 1) 拉代码
scp alihz:/opt/qq-bridge/src/bridge.js .
# 2) 写补丁脚本（精确串替换 + 命中数断言，不符就不写盘）
python patch-xxx.py            # 产出 bridge-patched.js
node --check bridge-patched.js
# 3) 隔离副本测试（绝不碰生产 state）
bash run-xxx-server.sh
# 4) 备份 + 部署
cp src/bridge.js src/bridge.js.bak-$(date +%Y%m%d-%H%M%S)
cp bridge-patched.js src/bridge.js

# 5) 验活
systemctl is-active qq-bridge; pgrep -f 'src/bridge.js'
tail -30 /var/log/qqbridge.log
```

**补丁脚本必须这样写**（这是防手滑的唯一保险）：

```python
def rep(old, new, expect, label):
    n = t.count(old)
    if n != expect:
        raise SystemExit(f'[{label}] 命中 {n} 处，期望 {expect}，未写盘')
    return t.replace(old, new)
```

## 9. 给下一个接手的人

1. **别信"配置改了就好了"**——先确认守护进程和桥接都重启过、且读的是新值。
2. **别在以为"没有 unit"的时候走 `pkill + setsid`**——上次这么干把桥接摘出 systemd，
   野进程占住 `state/bridge.lock` 和 3100 端口，systemd 无限重启。正确顺序：
   `systemctl stop` → 确认进程没了 → `rm -f state/bridge.lock` → `reset-failed` → `start`。
3. **别把凭据打进日志或对话**。要确认键是否存在，只打印键名。
4. **测试用自己的隔离副本**，别在生产 `state/` 上跑。
5. **验证失败先怀疑自己的调用节奏**——有一次"总数不涨"其实是限流（3 次/分钟）在工作。

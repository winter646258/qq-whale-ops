# 功能模块契约（`src/modules/`）

这个目录是「一个功能一个模块」改造的产物。`src/bridge.js` 里那条 1450 行的 if 链正在被逐族搬进来，
新功能**不要再往 if 链里加**，写成模块。

改这个目录之前，先读完这份契约。里面每一条都是踩过坑之后才写下来的，不是风格偏好。

---

## 1. 一个模块长什么样

```
src/modules/<名字>/index.js
```

```js
export default {
  name: 'tokens',                    // 必填，唯一
  title: 'Token 用量账本',            // 给 /api/_modules 看
  inject: ['cfg', 'log', 'tokenLedger'],  // 装载期校验的依赖
  routes: [
    { method: 'GET',  kind: 'exact',  path: '/api/tokens/summary', handler: summary },
    { method: 'POST', kind: 'exact',  path: '/api/tokens/reset',   handler: reset },
  ],
  setup(ctx) { /* 可选，装载期校验 */ },
  teardown(ctx) { /* 可选 */ },
};
```

装进 `src/modules/index.js` 的 `defineModules()` 数组即可，**不用改 `bridge.js`**。

## 2. handler 的签名（最容易写错的一条）

```js
async function summary({ req, url, sendJson }) {   // ← 第一个参数是注入包
  if (rejectAgent({ req, sendJson })) return;
  sendJson(this.ctx.tokenLedger.summary());        // ← ctx 在 this 上，不在参数里
}
```

- **第一个（也是唯一一个）参数**是 `{ req, res, url, sendJson, readBody }`。
  `sendJson` / `readBody` 是请求回调里的**局部变量**，`main()` 作用域里根本不存在，
  只能从参数拿，**不能放进 ctx**。
- **`ctx` 在 `this` 上**：`this.ctx.xxx`。它是装载器用 `{ ...def, ctx }` 当 receiver 绑上去的。
  写 `async function h(ctx, { req })` 会拿到 `undefined` 并报
  `Cannot destructure property 'req' of 'undefined'`。

## 3. `inject` 的写法与陷阱

```js
inject: ['cfg', 'log', 'stateDir', 'fs', 'path', 'dshHelpers'],
```

- 装载器会检查每个键是否真的在 ctx 上，缺一个就在启动期报 `ctx 缺少依赖：xxx`。
  **只告警，不阻断**其它模块装载 —— 装不上的那个模块的路由不生效，其余照常。
- **不要奢望 `rooDir` 之类自己编的键**：写错名字不会崩，只会记一条 problem，
  然后运行时 `ctx.rooDir` 是 `undefined`，等到半夜才炸。写 `inject` 前去
  `grep "MARKER: modules-ctx" src/bridge.js` 看现在到底交了哪些键。

### 会被整体重新赋值的 `let` 必须交访问器

```js
// bridge.js 里
Object.defineProperty(moduleCtx, 'state', { get: () => state, enumerable: true, configurable: true });
// 会整体重新赋值的变量，交闭包而不是快照值
currentMode: () => currentMode,
bumpModelSelectionEpoch: () => { modelSelectionEpoch += 1; },
```

`state` / `dshPresetIds` / `dshDefaultPreset` / `modelCatalogInFlight` /
`modelSelectionEpoch` / `currentMode` / `roleInjectMaxChars` 都属于这一类。
直接 `Object.assign(moduleCtx, { state })` 会把**旧对象冻住**。

### 只建一次、之后只调方法的 `const` 可以交引用

`tokenLedger`、`priceTable`、`pending`（Map，只 add/delete/clear）、`api` —— 安全。

## 4. 拒绝智能体：口径必须逐字一致

所有控制台接口在 handler 开头写：

```js
function rejectAgent({ req, sendJson }) {
  if (req.headers['x-agent-call'] !== undefined || String(req.headers['x-agent-token'] ?? '') !== '') {
    sendJson({ ok: false, error: '该接口仅控制台可用' }, 403);
    return true;
  }
  return false;
}
```

**为什么不能只判 `x-agent-token === undefined`**：MCP 端在缺令牌时会带
`x-agent-call: 1` + 空串令牌（见 `bridge.js` 里 x-agent-call 闸门的注释）。
只判 `undefined` 就等于「漏传令牌 → 升级成控制台全权」，正是那个闸门要堵的
confused deputy。这条是审查时统一过来的，六个模块必须一模一样（`md5sum` 可核）。

例外：`/api/authorize/read` 在 agent 白名单里（`bridge.js` 的 `agentAllowed`），
它**不做** `rejectAgent`，改为 key + token 双校验。

## 5. TDZ：注入点之后才声明的名字

`bridge.js` 里 `Object.assign(moduleCtx, {...})` 分散在多处，位置取决于相关声明何时出现。
**注入点之后才声明的名字，只能出现在函数体里，不能出现在对象字面量的值位置。**

```js
// ✗ 崩：pending 声明在 L9540，注入点在 L2829
Object.assign(moduleCtx, { pending });

// ✓ 在函数体里（调用时已过 TDZ）
loadModelCatalog: async () => { modelCatalogInFlight = ...; },
```

踩过的真实报错：`ReferenceError: Cannot access 'pending' before initialization`。

---

## 6. 作用域：`main()` 里的局部变量拿不到

`agentTokenOk` / `isLiveAgentToken` 是 `startConsoleServer()` 里的**局部 const**。
第一版以为是 `main()` 的，结果 `ReferenceError: agentTokenOk is not defined`。

拿不到的，在对应作用域里补一句 `Object.assign(moduleCtx, { ... })`，别在模块里 import。

---

## 7. 路由优先级

装载器按**固定规则**匹配，**不靠**文件里的先后：

1. `exact` 优先于 `prefix`
2. 同 `exact` 按路径字典序
3. `prefix` 按长度降序
4. 同级按注册序

所以 `/api/socialV2/state` 永远赢过 `/api/socialV2/`，与 if 链的书写顺序无关 ——
这正是这次改造要解决的隐式契约风险。前缀互相遮蔽会在 `problems` 里记 `route-shadow`。

**回去看状态**：`GET /api/_modules`（免登录只读诊断，不含令牌/聊天内容/路径）。

---

## 8. 禁止 import `bridge.js`

会触发第二次 `main()`，循环 import，进程直接起不来。
需要主文件里的函数，由 `bridge.js` 通过 `Object.assign(moduleCtx, {...})` 交出去。

---

## 8.5 委派点在哪（这条最容易在阶段之间被打破）

`// MARKER: modules-delegate` 的位置不是随意的，它决定了**模块路由会被哪些闸门覆盖**。
当前它必须在下面这一整串之后：

```
favicon 处理
  → 控制台令牌闸门（tokenMatches / 401）
  → 智能体调用隔离段（含：空令牌拒绝、paused、socialV2.enabled=false、
      reserved2 模式、adminOnlyV2Paths、/api/stickers* 仅控制台）
  → ★ modules-delegate
  → 第一条普通业务路由（老 if 链）
```

**为什么**：这条改装（阶段 8）踩了两次同一个坑，两次都是「模块路由比闸门跑得早」：

1. 委派点最初放在 favicon 之后，看着像「在所有闸门之后」，其实 favicon 在 4636 行、
   令牌闸门在 4823 行，中间隔着整段鉴权。结果 `GET /api/stickers` 的匿名身份
   从 `401` 变成了 `200` —— 任何人都能匿名读到 2179 条表情元数据。
2. 把它挪到令牌闸门之后，仍然漏了后面那一段**智能体隔离闸门**。结果
   `agent token` 打在 `/api/stickers` 上从 `403` 变成 `200`。
   模块里的 `rejectAgent` 只能挡「从模块侧看是智能体」的调用，挡不住集中闸门
   本来要挡的那一类。

**判断标准**：搬一条路由进模块前，先在 `bridge.js` 里量出这条老 if 的缩进深度，
再确认委派点的缩进 ≤ 它 —— 委派点如果比老路由浅，就说明你**抢先**了，那条路由
原本享受的闸门会全部失效。缩进 8 是普通业务路由，缩进 6 是集中闸门。

## 9. 回退开关

```json
{ "socialV2": { "modules": { "enabled": false } } }
```

关掉后一个模块都不装载，请求整段跳过委派、走老 if 链。
注意：`POST /api/socialV2/config` 传 `{"socialV2":{"modules":{...}}}` 会**嵌套错位**
（`saveConfig` 把整个 socialV2 对象浅合并进 `file.socialV2`），要直接改 `config.json`。

## 10. 改完必须跑的三件事

```bash
node --check src/modules/<名>/index.js
node scripts/golden-routes.mjs --out state/golden-routes-now.json
node scripts/compare-routes.mjs state/golden-routes-<上一阶段>.json state/golden-routes-now.json
node scripts/snapshot-wake-prompt.mjs --compare state/wake-prompt-baseline.json
```

- **每搬完一批，要把路径补进 `scripts/compare-routes.mjs` 的 `EXPECTED_MOVED`**，
  否则正常搬家会被报成 `✗ MISSING`，回归就失去意义。
- 服务起不来时 systemd 只给 `status=1/FAILURE`，看不到栈。
  **先 `systemctl stop qq-bridge`，再 `timeout 25 /usr/bin/node src/bridge.js`** 才能看到
  `[bridge] 启动失败: ...` 和精确行号。

**搬族已经结束。** `scripts/classify-routes.mjs` 现在只剩 `root-page` 2 条，
而且是**故意不搬的**：两处 `GET /` 分属不同闸门阶段 —— 一处在控制台令牌校验**之前**，
作用是未授权时返回 401 提示页；另一处在校验**之后**，返回真正的控制台页面。
它们不是一个「业务接口」，而是鉴权流程的一部分，搬进模块就必须复制鉴权顺序，
正好违反第 8.5 节那条「委派点必须落在全部闸门之后」。

`bridge.js` 从 14622 行 / 818283 字节降到 **10654 行 / 550859 字节**。
模块代码共 **37 个文件 / 5526 行**，在 `src/modules/` 下。

**同一个功能的两个面要拆成两个模块**：表情库就是例子。控制台那 4 条走
`x-console-token`、AI 那 5 条走 `x-agent-token` + 三条会话级校验，鉴权口径
完全不同，塞进一个模块只会让人写错 `rejectAgent`。拆开之后，模块名本身就
说明了「这是给谁用的」。

`/api/socialV2/` 那一族里，凡是「她自己用」的接口（memory / mood / spotify /
slang 查询 / share / forward / image）都按用途分散进了对应模块，而不是堆成
一个大 `socialV2` 模块 —— 那样会得到一个和 `bridge.js` 一样难改的东西。

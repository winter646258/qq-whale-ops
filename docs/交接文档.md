## 五、访问控制：三级准入（自己改的代码）

| 层 | 判定函数 | 规则 |
|---|---|---|
| **被动收消息** | `allowed()` | `friendOnly=true` ⇒ **任何好友都能发消息**；陌生人拒绝 |
| **主动找人** | `proactiveAllowed()` | 只限 `allow.private` 白名单；且**只拦 `proactiveCheck`** |
| **封闭模式** | `modeAllowed()` | `closed-agent` 时仅 `ownerQQ` |

### ⚠️ 三个必须记住的坑

**坑 1：`friendOnly` 必须在 cfg 归一化里注册**

```js
// bridge.js 的 cfg 构建处（约 660 行）
allowAllWhenEmpty: file.allowAllWhenEmpty === true,
friendOnly: file.friendOnly === true,      // ← 少了这行，判定恒为 undefined
```

**坑 2：主动白名单只能拦 `proactiveCheck`**

```js
// sendWakePromptV2 里
if (reason === 'proactiveCheck') {         // ← 不能把 bootstrap/private/poke 也拦了
  ...proactiveAllowed 判定...
}
```

`bootstrap`/`private`/`poke`/`replyCheck`/`timeout` 都是**应答**，必须放行；只有 `proactiveCheck` 是"AI 自己想冒泡"。

**坑 3（本次新修）：刚通过好友申请的人会撞上「好友列表刷新窗口期」**

- 现象：某人 15:38 通过好友申请，15:42 发的消息仍被 `忽略未授权会话` 丢弃。
- 原因：好友列表由 `get_friend_list` **定时**拉取，旧间隔 **10 分钟**，新好友最多 10 分钟进不了 `friendSet`；而 `friendOnly` 对非好友 fail-closed。
- 修复（2026-10-19，bridge.js）：
  - `FRIEND_REFRESH_MS` 10 分钟 → **1 分钟**
  - 命中「非好友发来消息」时**立刻补拉一次**好友列表（去抖，与定时刷新共用一把闸），让**下一条**消息能过；本条仍丢弃（身份未确认不放行）
  - 补丁脚本留档：`aliyun-chaoxing\patch-bridge-friend-refresh.py`
  - 备份：`/opt/qq-bridge/src/bridge.js.bak.20261019-171349`

在原有 19 张（`mfuns-*`）基础上，导入 **2141 张**大肥鱼 / DeepSeek娘梗图。

| 项目 | 内容 |
|---|---|
| 数据源 | `https://aigengtu.com/gallery-index.json`（梗鲸图库，2141 张，12 个分类） |
| 作者仓库 | `github.com/the-beating-light-of-the-nail/deepseek-chan-meme-pack`（只含 20 张预览 + 目录，真图在 CDN） |

| id 规则 | `aige-<编号>`，与原有 `mfuns-*` 不冲突 |
| 字段填充 | `desc` = 图库台词；`localNote` = 从中文梗科普压出的「适用：…」（771 张有）；`tags` = 分类 + `deepseek/鲸鱼娘/大肥鱼` |

**为什么 2160 张不会撑爆上下文**（关键）：
- `buildStickerContext()` 有硬上限 —— 默认只注入 **8 条**，最多 30 条（`promptMaxStickers` 配置项）

### ⚠️ 2026-10-19 晚：限流事件暴露的两个真漏洞（已修）

**事件**：19:09–20:04，CodeBuddy 的**全部账号被限流**，AI 完全不能说话。

```
⚠️ agent 处理出错：CodeBuddy (腾讯)：模型 deepseek-v4.1-flash 的可用账号均在限流中，
   最近一个将于 2026/10/19 20:04:11 解禁。可改用其它 provider / 模型，或等待解禁后再试（无需重新登录）。
```

**漏洞 1：报错根本没进日志（根因）**
桥接的 agent 错误分支只做 `sendToQQ(key, '⚠️ agent 处理出错：…')`，**不写 stdout**。
实测：`/var/log/qqbridge.log`、`state/bridge.log`、`state/qq-activity.log`、`state/feedback.json`、`state/tool-calls.jsonl` 里 `grep 限流` **全部为 0**。
水位线机制看不到失败 ⇒ 它一直认为"一切正常"，**自动切换形同虚设**（被限流 1 小时没兜住）。
修复：`bridge.js` 的错误分支加 `log()` + `appendActivity()`（补丁脚本 `patch-bridge-log-agent-error.py`，备份 `bridge.js.bak.20261019-200511`）。

**漏洞 2：失败关键词表漏了"限流"**
原表：`unauthorized|quota|insufficient|balance|额度不足|发送失败|AI 反馈.*error`
现表：追加 `rate.?limit|限流|解禁|所有账号|可用账号|余额不足|agent 处理出错`

## 十七、表情候选池「日期轮换」修复（2026-10-20）

### 症状

表情库有 2160 张，但注入给 AI 的候选池**永远是那 19 张 mfuns 老图**，
2141 张 aige 新图一张都进不来 —— 她不是不发，是手上根本没得挑。

### 根因（死锁）

`src/sticker-lib.js` 的 `buildStickerContext()` 只按 `useCount` 降序取前 N：

```js
.sort((a,b) => (b.useCount||0)-(a.useCount||0) || ((b.desc||b.localNote)?1:0)-…)  // 第一权重：用过几次
.slice(0, 8)   // promptMaxStickers 默认 8
```

`aige` 全部 `useCount = 0` ⇒ 永远排在 `mfuns` 后面 ⇒ 挤不进前 8 ⇒ 永远没机会被用。
**没用过 → 不进池 → 没机会用 → 还是没用过。**

### 实测数据（决定阈值）

| 项 | 数值 |
|---|---|
| 表情总数 | 2160（`mfuns` 19 + `aige` 2141） |
| 全部有 `desc` | 2160 |
| **无信息量描述**（形如 `DeepSeek娘『1000382674』表情包`，数字是导出侧图库 ID） | **416 张** |
| 干净轮换池 | **1744 张** |
| 图片可下可发 | 抽查 6/6 HTTP 200 webp 20~40KB |
| 历史上她发过 | 7 次（含 `aige-009`、`mfuns-17`、`aige-052`） |

### 改法（`patches/patch-sticker-rotation.cjs`）

- **头部**（`limit - mixTail` 个）：仍按质量排序的「用过的图」，保她熟悉的那几张稳定出现
- **尾部**（`mixTail` 个，默认 **3**）：从「干净轮换池」按**日期种子（UTC+8）洗牌**取
  - 同一天内**可复现**（不会来回跳），跨天自然换一批
  - 池子**不因"用过"而退出**，所以不会枯竭
- **质量门槛 `describeLess()`**：去掉包装字/数字/常见前缀后，中文不足 2 字 ⇒ 视为无描述，排除出轮换池
- 按 `desc/localNote` 去重；文案截断 60 字、标签截断 30 字，省注入空间

原因不在脚本，在**图库源数据本身就是空的**：

| 全图库 alt 形态 | 数量 | 占比 |
|---|---|---|
| 正常（有真实文案） | 1367 | 64% |
| 无括号内容（如 `AI娘表情包`） | 549 | 26% |
| 纯数字（`『1000382674』`＝图库 ID） | 206 | 10% |
| 哈希（`『efb57863…』`） | 29 | 1% |
| **合计非正常** | **784** | **36%** |

对这 416 张逐条核对图库原始对象：

```json
{"alt": "DeepSeek娘『1000382674』表情包", "name": "同上",
 "preview": "https://img.aigengtu.com/0_preview/meme/161.webp",
 "category": "DeepSeek娘"}
```

- **412 张连 `story.zh` 都是 `None`**（只有 4 张有）
- `story.en` / `story.origin` / `story.contributor` **全部为空（0/416）**
- 即：图库没给这些图写任何文案，**没有可填的内容**

量化结果：`desc 可从图库补全 0 条`、`localNote 可补全 0 条`。
**说明当初的导入是干净的 —— 图库给什么就导了什么，没丢东西。**

**① `import-memes.py` 加质量兜底**（`describe_less()`）

（先去哈希、再去长数字），否则两边对「干净」的定义会漂移。

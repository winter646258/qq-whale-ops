## 1. 这是什么

一个 QQ ↔ DeepSeek Harness（DSH）的桥接程序。它把一个 LLM 接进 QQ 群和私聊，并给她一套
「像人一样活着」的机制：判断该不该说话、记住人和事、有自己的情绪和日记、能生图发语音发动态。

**核心人格**：小鲸鱼 / 昵称「大肥鱼」，QQ `2157801858`。
**主人**：QQ `1124721191`（`ownerQQ`）。

### 1.1 部署拓扑

```
QQ 客户端（容器内 Electron）
   ↕ OneBot v11（HTTP 3000 / WS 3001）
SnowLuma（Docker 容器 snowluma，非 systemd）
   ↕ WebSocket
qq-bridge  (systemd: qq-bridge.service, node src/bridge.js, 127.0.0.1:3100)
   ↕ HTTP/SSE 127.0.0.1:3081
DSH Web (systemd: qq-dsh.service)
```

### 2.3 模块契约

**必读**：`docs/模块契约.md`（11 节，全部是踩坑后写的）。核心几条：

1. **handler 签名**：第一个也是唯一参数是 `{ req, res, url, sendJson, readBody }`，`ctx` 在 `this` 上。
   写成 `(req, res)` 会拿到整个对象 ⇒ `Cannot read properties of undefined (reading 'x-agent-call')`。
2. **`inject` 里的名字必须在注入点之前已声明**，否则 TDZ 崩溃。
   会被整体重新赋值的 `let`（`state`/`currentMode`/`social`/`dshReady`/`stickerEntries`…）
   **必须交访问器** `currentMode: () => currentMode`，不能交快照值。
3. **`rejectAgent` 只判 `=== undefined` 是错的**（`x-agent-call: 1` + 空令牌会放行）。
   统一写法：
   ```js
   if (req.headers['x-agent-call'] !== undefined || String(req.headers['x-agent-token'] ?? '') !== '') {
     sendJson({ ok: false, error: '该接口仅控制台可用' }, 403); return true;
   }
   ```
4. **dispatch 约定是 `'handled'` / `'unhandled'`**。`return false` 会被当成未处理
   （曾让 `POST /api/slang/<id>` 落回老链路挂满 15 秒）。
5. **模块内 catch 必须透传 statusCode**：`Number(error?.statusCode) || 500`。
6. **禁止 `import` bridge.js**（会循环依赖）。

### 2.4 12 道集中鉴权闸门

全部在 `src/bridge.js` 的 `startConsoleServer()` 请求回调内，模块委派点（`MARKER: modules-delegate`）
**必须排在这 12 道之后**，否则模块路由会绕过鉴权（踩过两次，见 §5.1）。

`favicon 204` → `/api/_modules`（免登录只读诊断）→ Host 校验 → 控制台令牌（`?token=` 优先，
`timingSafeEqual`）→ `x-agent-call` 校验 → CSRF（非 GET 必须 `application/json`）→ 空 agent token 403
→ `paused` → `socialV2.enabled===false` → 非 reserved2 → `adminOnlyV2Paths` → `/api/stickers*` 仅控制台
→ **模块委派** → 老 if 链 → 404。

- `adminOnlyV2Paths` = `/api/socialV2/{config,activity,reset,states,wake}`
- agent 白名单（`agentAllowed`）= `/api/status`、`/api/socialV2/`、`/api/send/`、`/api/images/`、`/api/authorize/read`
- `/api/phone/*` 走独立 `x-phone-token`，被 `phonePathExempt` 放行
- **agent 进程同时握有 `x-console-token`** ⇒ 集中闸门挡不住它，凡控制台接口必须在 handler 里自己 `rejectAgent`

## 3. 「像人」的机制清单

### 3.1 该不该说话（参与决策）

`evaluateWakeTriggerV2`（`src/bridge.js`）**顺序短路**，命中即返回：

```
private → anyMessage → atMention → isDirectedAtOthers 抑制
  → nameMention（走 maskOtherMemberNamesV2 撞名掩码）
  → keywords（带撞名掩码）→ question → speakerIds → probability
```

配套：

- `bot-mutex`：群里其他 bot 的消息直接返回 `null`，不唤醒（`get_group_member_list` 拉 `is_robot` 缓存 30 分钟）
- `replyCheck`：`autoReplyCheckMsInGroup`（本群 420s）定时回头看一眼有没有该回的
- `proactive`：主动冒泡，四道硬闸（最小间隔 45min / 每小时 2 条 / 23–8 点静默 / 概率封顶 0.5）
- `mark_read` / `readThroughSeq`：未读水位
- `pendingWakeReasons`：唤醒原因队列，每 30s 清扫

### 3.2 情绪（`src/mood-store.js`）

PAD 三维模型（pleasure / arousal / dominance，各 −1..1）。

- `baseline` 长期底色，**只能显式改，不自动漂移**（有注释说明为什么）
- `pad` 当前心情，按指数回归向 baseline 衰减
  `v(t) = baseline + (v0 - baseline) * 0.5^(Δt / halfLife)`
  半衰期按偏离幅度分三档：强 90min / 中 45min / 轻 20min；单次底色步长上限 `BASELINE_STEP_LIMIT = 0.05`
- `undercurrent`（权重数组，上限 `MAX_UNDERCURRENT = 20` 条）：压着没说出口的事，超阈值 `UNDERCURRENT_ALERT = 1.5` 提醒
- `label`（≤20 字）+ `reason`（≤120 字）

### 3.3 记忆

| 层 | 位置 | 机制 |
|---|---|---|
| 会话内 | DSH session | 私聊/群聊各自独立上下文 |
| 记忆条目 | `state/social-v2.json` → `conversations[k].memory` | `activeTopic` / `pendingThought`（带 expiresAt）/ `memberImpression`（≤40 条 × ≤20 字） |
| 自动记忆 | `src/auto-memory.js` | **代码层**正则抽「称呼/要求/约定/偏好」四类，每回合 ≤1 条；命中系统注入段整条跳过；带隐私词的只进 `owner_private` |
| 日记 | `src/diary-store.js` | 分档 `normal(半衰 5 天) / important(21 天) / critical(永存)`，`FADE_THRESHOLD` 以下淡出 |
| 跨会话共享 | `src/shared-memory-store.js` | `state/shared-memory.json` |
| 群摘要 | `src/group-digest-store.js` | 潜水回来后接上下文 |
| 好感度 | `src/affinity-store.js` | 1–10 分档，**只给档位语气，不把数值给模型** |

### 3.4 表达

- **角色卡** `roles/小鲸鱼.md`（6847 字符，253 行，10 章）。**热生效**，改完下一次唤醒即生效。

  现文案：「分句用半角空格，不用逗号串长句；一条消息控制在两句以内。」
- **唤醒提示 20 段**：`roleLine + tokenLine + antiAiLine + proactiveLine + stickerLine + replyLine +
  statusLine + moodLine + imageLine + wakeLine + memoryLine + sharedMemoryLine + affinityLine +

- 生图、表情包、语音、说说（`qq_qzone`）、Spotify（`qq_spotify`）

### 3.5 会话收敛（P0 守卫）

## 5. 踩过的坑（血泪清单）

### 5.1 模块委派点位置（越权两次）

`MARKER: modules-delegate` 放错位置 = 模块路由绕过全部闸门。

1. 放 favicon 之后 ⇒ `GET /api/stickers` 的匿名从 **401 变 200**，可读 2179 条表情元数据。
2. 放令牌闸门之后、**智能体隔离闸门之前** ⇒ agent token 打 `/api/stickers` 从 **403 变 200**。

**判断标准**：搬一条路由前先量老 if 的缩进深度，委派点缩进必须 ≤ 它（缩进 8 = 业务路由，6 = 集中闸门）。

### 5.2 阶段 27 事故：整段删除 + 部分搬运

模块化搬 `config → forward-message` 时删掉 1957 行，只搬了 13 条，**14 条路由连带消失**
（send-message / send-sticker / send-poke / send-burst / record-sent / check-send / collect-sticker /
wait / diary / album / schedule / portrait / qzone / send-voice），MCP 8 个工具全 404。

- 掩盖原因：把这 14 条误判成「误抽路由」，补进 `compare-routes.mjs` 的 `EXPECTED_MOVED`，尺子自洽了。
- 修法：从 `src/bridge.js.bak-core-1792812995334` 按行号挖回 12 块 / 1197 行。
- **原注释逐字**：「后续要模块化必须连同 ctx 一起设计，不能再来一次「整段删除 + 部分搬运」」。
- 现有回滚点：`MARKER: v2-rest-rollback`。

### 5.3 `kind is not defined` —— 群消息被整条吞掉

P1 bot-mutex 补丁里写 `isBot: kind === 'group' ? ...`，但 `appendSocialV2Message` 签名里没有 `kind`。
异常抛在落库之前 ⇒ **整条群消息既不入库也不唤醒**，日志只有一行 `处理群消息出错: kind is not defined`。
改成判 `String(key).startsWith('group:')`。
**教训**：语法检查抓不到未定义变量，改完必须等真实消息流过一次。

### 5.4 其它高频坑

| 坑 | 表现 | 正解 |
|---|---|---|
| `startConsoleServer()` 不是 async | `SyntaxError: Unexpected reserved word` | 模块装载写在 `main()` 里、调用点之后 |
| ssh 单参数 >32KB | `Program 'ssh.exe' failed to run: 文件名或扩展名太长` | 用 `base64` 分块或 `ssh "base64 -w0 <path>"` 取回 |
| 服务起不来无栈 | systemd 只给 `status=1/FAILURE` | `systemctl stop` 后 `timeout 25 /usr/bin/node src/bridge.js` |
| 前端 `ReferenceError` 静默 | 接口 200 但面板空白 | 脚本初始化挪到 `DOMContentLoaded` |
| 补丁脚本只认 MARKER | 改注入块后重跑静默复用旧块 | 用 python/sed 定点修补，别指望脚本重跑 |
| `preSleepLine` 与 `preSleepWaitEnabled` 矛盾 | 提示词逼她等观察窗口，配置早已关闭 | 已改为跟随开关（`MARKER: pre-sleep-hint-follows-flag`） |

## 7. 已知未修问题

### 7.1 桥接 WS 断开后不自愈（**高**）

SnowLuma 上报 `bot_status: offline` 后主动 `code=1000` 断开 WS，桥接日志只有 `重连中…`，
之后再无「已连接」，**必须人工 `systemctl restart qq-bridge`**。
2026-10-25 上午连续踩了三次。
注意：`/api/status` 的 `accountOnline` / `good` 在 WS 断着时仍报 `true`，**只有 `connected` 和
`lastPacketAgoMs` 才是真链路指标**。

### 7.2 provider 被守护脚本覆盖（已缓解）

`switch-provider.sh` 每 60s 检查，`config.json` 的 `dsh.provider` 不在 `CHAIN_PROVIDERS` 里就
**强制改回链首并 restart 桥接**。
现链：`(loomy trae raccoon our-free-model)` / `(DeepSeek-V4.1-Flash deepseek-v4.1-flash
sn-deepseek-v4-1-flash deepseek/deepseek-v4.1-flash)` / `(low light on light)`。
**改 provider 必须同时改这个脚本**，改完 `systemctl restart qq-provider-switch`。

### 7.3 其它

| 问题 | 影响 | 备注 |
|---|---|---|
| `phone` 3 条 `route-shadow` | 无 | `OPTIONS` 前缀遮蔽 exact，`match()` 先判 method 且 exact 优先 |
| phone `OPTIONS` 预检被 CSRF 闸门拦 | 扩展若不发 `content-type` 会收 415 | 修法要把预检放回闸门之前，等于开洞，待评估 |
| `/api/voice/send` 接受任意外部绝对路径 | 可把 `/etc/passwd` 之类交给 ffprobe | 是否收紧到「只允许语音库内文件」待定 |
| `/api/preset/sim-prompt` 无参返 500 | 既有行为 | `standard` 是回退默认名，带参正常 |
| 跨会话搜聊天正文做不到 | `search` 只搜角色卡/黑话/记忆/活动流 | 活动流只存系统日志，不存聊天正文 |

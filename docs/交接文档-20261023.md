## 5. 关键机制（改代码前必须知道）

### 5.1 三层作用域（最容易踩）
```
bridge.js 模块层（缩进 2）
  cfg / currentMode / socialV2 / selfUserId / onebotSend / pending / allowed
  friendSet / generateImageNow / v2ToolEnabled / imageSceneFor / imageAllowedNow
  affinityStore / sharedMemory / shareSignal / groupDigest / imageApproval / phoneBridge

  └── startConsoleServer()（缩进 4）
        tokenEq / agentTokenOk / isLiveAgentToken   ← 这里才有！
```
所以写在模块层的函数**看不见** `tokenEq`，要比较令牌得自己 `crypto.timingSafeEqual`（`import crypto` 在 `bridge.js:12`）。

### 5.2 `bounded()` 是局部的，别在模块层用
`bounded` 定义在 `buildWakeSnapshotV2` 内部（缩进 4）。在模块层调用会在**每一条唤醒 prompt 的必经路径**上抛 `bounded is not defined`。
曾经因为这个，主人私聊的唤醒全部失败。现在 `buildSharedMemoryLineFor` 已经改成就地夹紧。

### 5.3 三层生图闸门
```
① deliverPromptNow 开头 → 无条件写 __qqTurnContext + 打「授予额度」日志（只是日志！）
② /api/socialV2/image   → imageAllowedNow() 真判定（回合上下文 / 宽限 / scene）
③ imageSceneFor         → owner-private / owner-group / null
```
**「授予额度」不是判定** —— 我拿它统计过「给了 107 次额度、0 次请求」，那是错的，它只是回合数。

### 5.4 `turn/end` 驱动
- `turn/start` → 记 `v2TurnStartAt`
- `turn/end` → 清 `__qqTurnContext`，同时写 `__qqTurnContextEnded = { key, reason, at }`（**reason 必须一起存**，宽限分支要拿它判 byMention）
- `imageAllowedNow` 的顺序：`__qqTurnContext` → 过期则看 `__qqTurnContextEnded` + `turnGraceMs`（默认 90s）

### 5.5 四种令牌，别搞混
| 令牌 | 头 | 文件 |
|---|---|---|
| 控制台 | `x-console-token` | `state/console-token`（48 字符） |
| 会话 | `x-agent-token` | `state/social-v2.json` 每个会话的 `agentToken` |
| 浏览器桥 | `x-phone-token` | `state/phone-token`（49 字节，懒生成） |
| DSH web | `?token=` / Bearer | `/var/log/dsh-web.log` 最后一行 |

**`/api/socialV2/send-*` 读的是 header，不吃 body 里的 `token`** —— 用 curl 传 body 会报 `reserved2 模式发送必须携带 agent token`。

### 5.6 `friendOnly` 优先于白名单
```js
if (kind === 'private' && cfg.friendOnly === true) {
  if (!friendSetReady) return false;      // 好友表未就绪 → fail-closed
  if (friendSet.has(s)) return true;      // 是好友 → 放行
}
const allowList = cfg.allow[kind] ?? [];
if (allowList.length > 0) return allowList.map(String).includes(s);
return cfg.allowAllWhenEmpty;
```
所以「好友」比 `allow.private` 优先级高 —— 3414115838 不在白名单里但**确实是好友，能过准入**。
`friendOnly` 只放宽**被动收消息**，「主动找谁」由 `proactiveAllowed()` 用白名单单独把关。

### 5.7 `sweepPendingWakeReasons` 是 reserved2 下唯一的巡检
`socialLoopTick` 只在 `currentMode === 'reserved'` 下有意义，而当前是 `reserved2`。
所有需要「定期检查」的功能（主动档期补排、主动报告投递）都挂在 `sweepPendingWakeReasons` 末尾，30 秒一轮。

### 5.8 唤醒频率硬限
`HIGH_PRIORITY = new Set(['private', 'atMention', 'question'])` —— 这三个超限只打日志不拦。
其余受 `maxWakePerMinute=1`、`maxWakePerHour=12`、`maxWakePerHourInGroup=8` 限制。

### 5.9 会话缓存不落盘的那几个
`shareStateCache` / `affinityCache` / `imageApprovalCache` / `phoneBridge` / `friendSet` / `friendSetReady` 全是内存变量。
**直接改 `state/*.json` 不生效，必须重启。**

## 6. 二十条坑（血泪，按痛感排序）

### 6.1 万能桩会吞掉真实作用域错误
写了个用 Proxy 兜住所有未声明标识符的验证 harness，`bounded` 被喂成桩函数 → **测试全绿、线上每轮唤醒都抛错**。
**验证要用「括号配对抽真实函数 + 真数据」的 harness，不要用万能桩。**

### 6.2 语法花括号配平 ≠ 语义没坏
补丁把 `if (reason === 'poke') {` 复制成两层，`node --check` 照样通过 —— 外层 if 把 poke 分支和最后的通用 `return` 全包进去，**任何非 poke 的 reason 都返回 undefined**。
发现方式：抽函数看长度，88358 字符（正常 11816）。
**带锚点插入必须断言锚点唯一性**：`ensure(SRC.count(anchor) == 1)`。

### 6.3 `apply(before=False)` 是替换语义
`SRC.replace(anchor, addition, 1)` 会把锚点整行换掉，所以 `addition` 必须自己把锚点行原样放回。
更狠的一层：`IMPORT_ANCHOR = "} from './xxx-store.js';"` 是 import 的**收尾行**，把新 import 写它前面等于往未闭合的大括号里塞 `import` 语句。
**正确顺序：先锚点行，再新 import。**

### 6.4 `node --check` 在 /tmp 下什么都不检查
无 `package.json` 时 Node 按 CJS 解析 `.js`，对含 `import` 的文件**直接返回 0**。
必须 `printf '{"type":"module"}' > package.json`。线上 `/opt/qq-bridge/package.json` 是 `"type": "module"`，检查才是真的。

### 6.5 补丁「已装，跳过」是死结
文件里装了旧内容（带 bug），补丁因 MARKER 命中而跳过 → 永远修不好。
解法：**手工修线上文件**，再让补丁补上。

### 6.6 回滚备份不能跨修复版本
拿 `bridge.js.bak-phone-...-120710`（早于 rawPath 修复）回滚，会把已修的 bug 又带回来。

### 6.7 MARKER 不能有前缀关系，且必须是合法 JS 注释
`imgapprove-tool` 是 `imgapprove-tool-desc` 的子串 → 第二处被误判「已装」。
写成 `#` 或写进单引号字符串里会直接 SyntaxError。

### 6.8 日志没有日期，跨天会串台
`/var/log/qqbridge.log` append 不 rotate，`10:33:18` 可能是昨天的。曾把 10-21 的 `sessionController is unavailable` 当成今天的新故障。
**必须按「桥接已启动」行号分段。**

### 6.9 `grep -c` 数的是行数不是次数
HTML 是一整行，`grep -c "b_algo"` 返回 1，实际出现 10 次。差点误判搜索解析器坏了。

### 6.10 生产重启会打断长任务
12:22 那三次「生图请求」全无结果，不是 bug —— 是我 12:23:44 重启服务，36 秒的生图被 SIGTERM 掐断。
**重启前先看有没有正在跑的长任务**（生图 36~50 秒、黑话研究最长 12 分钟）。

### 6.11 装 DSH 插件会触发热重排
`dsh plugin add` 期间 host 侧 HMR 默认开着，会重排插件树。`dsh-native-memory` 的 patch 整体替换了 `session-query-sqlite` 配置，而 `sessionController` 的 inject 里有 `sessionQuery` → 整条依赖链断掉，挂了 83 分钟刷了 1660 条。
**装插件先 `systemctl stop qq-dsh`。**

### 6.12 `state/social-v2.json` 的 `conversations` 是**对象**不是 Map
线上 JSON 是对象，内存里是 Map。纯逻辑函数（如 `listGroupCandidates`）如果只写 `Object.entries`，**单测传普通对象全绿、真数据一跑就空，而且不报错**。
需要 `conversationEntries()` 统一处理 Map / 对象 / 数组。

### 6.13 主人判定必须 `isOwner && !isSelf`
`recordSentMessagesV2` 写她自己发的消息时 `isOwner: true` 也成立（`sender:'我'`、`isSelf: true`）。只查 `isOwner` 会把她自己的话当成主人在问群，导致循环注入。

### 6.14 中文正则别用 awk
经 ssh 传递会变成 `\u6865` 字面量，报 `regexp escape sequence '\u' is not a known regexp operator`。用 `python3` 判。

### 6.15 `ssh alihz` 频繁卡死
必须 `-o ConnectTimeout=30` + 重试 10~15 次 + `Start-Sleep -Seconds 3`。`scp` 同样，且**每次都要检查 returncode**（有一版漏了 check，静默失败，补丁沿用旧内容装上）。

### 6.16 反斜杠会被 shell 吃掉
`new RegExp('function\\s+' + name)` 经 ssh heredoc 传远端变成 `/\s+/` 字面量 → `SyntaxError: Invalid regular expression`。
**改用 base64 传脚本**：`echo '<b64>' | base64 -d > /tmp/x.mjs`。

### 6.17 pwsh 不支持 heredoc
`python - <<'PY'` 报 `Missing file specification after redirection operator`。本地多行 python 要写成 `.py` 文件再跑；远程 `python3 - <<'PY' ... PY` 可用。
`for ($f in @(...))` 也不支持，要 `foreach ($f in @(...))`。
PowerShell 写 UTF-8 默认带 BOM，要 `New-Object System.Text.UTF8Encoding $false`。

### 6.18 scp 拉源码前必须硬删
`Test-Path` 为真就跳过，会让断言失败的旧文件一直留着。

### 6.19 ESM 导出绑定只读
`H.allowPrivate = [...]` 报 `TypeError: Cannot assign to read only property`，测试里必须走 setter。
`export { x: (v) => {...} }` 也不合法，要 `const setX = ...; export { setX }`。

### 6.20 别把「日志说成功」当验证
`[image] 授予额度` 只是日志；`retcode:0` 也可能图没进群；`生图已发送` 之后还可能在 catch 里静默失败。
**每一步都要找到那行只有真跑通才会出现的日志，或者直接看数据文件。**

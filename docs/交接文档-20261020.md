## 五、五个已修复的关键坑（都踩过、都有实证）

### 坑 1：活跃群里的「等待死锁」⚠️ 最隐蔽

**机制**（`bridge.js` 的 `preSleepWaitBlockedV2` + `preSleepSatisfiedNow`）：

```
「沉睡前强制等待」规则要求她潜水前必须 wait 5 分钟观察窗口；
放行条件三选一，在活跃群里**永远不成立**：
  ① 距 lastIncomingAt 已安静 5 分钟   → 群一直有消息 ❌
  ② preSleepWaitSatisfiedAt 之后无新消息 → 该字段始终为空 ❌
  ③ preSleepWaitObservedAt 之后无新消息  → 同上 ❌
```

**后果链**：她反复 wait → **turn 永不结束** → 新唤醒全被「会话繁忙」暂存 → **新版策略永远送不进去**。

**实证**：13 次调用几乎全是 `wait(timeout=300000)`；session 日志里 12:16 之后只有 526 字符的收尾提醒，**没有一条完整唤醒提示**。

**处置**：热改 `wake.preSleepWaitEnabled = false`（已落盘）。修复后 13:00:29 首个完整唤醒（len=5856）送达。

### 坑 2：频率上限不分来源，把 @ 挤掉了

见 3.1 第三个补丁。**教训：给活跃场景加硬上限时，必须检查上限是否区分触发来源。**

### 坑 3：`/prompt` 接口 ≠ 唤醒提示词

`GET /api/socialV2/prompt` 用的是 `formatMemoryV2`，**不含** `buildWakePromptV2` 里的策略/印象提示。
**验证注入必须在唤醒提示里看**（可用 session 日志 `session.v4.jsonl.zstd` 解压核对）。

### 坑 4：SnowLuma 容器看不到宿主机文件

给网关传本地图**必须用 `base64://`**，`file://` 会报 `ENOENT`（容器内无此路径）。

### 坑 5：reserved2 模式发送必须带 `x-agent-token`

不带会 403 `reserved2 模式发送必须携带 agent token`。

## 七、操作手册

```bash
# ── 状态 ──
ssh alihz "systemctl status qq-dsh qq-bridge qq-zone-watch qq-provider-switch --no-pager"
ssh alihz "bash /opt/qq-bridge/whale-ctl.sh status"     # 四服务 + 桥接端口 + 总闸
ssh alihz "cd /opt/qq-bridge && node qzone-watch.js --limit"

# ── 一键闭嘴 ──
ssh alihz "bash /opt/qq-bridge/whale-ctl.sh pause"     # 立刻停止主动说话
ssh alihz "bash /opt/qq-bridge/whale-ctl.sh resume"

# ── 重启（走 systemd，别用 pkill+setsid）──
ssh alihz "systemctl restart qq-bridge"     # 改代码/config 后必须重启
ssh alihz "systemctl restart qq-dsh"

# ── 日志 ──
ssh alihz "tail -50 /var/log/qqbridge.log"
ssh alihz "tail -30 /var/log/qzone-watch.log"
ssh alihz "tail -20 /var/log/provider-switch.log"
ssh alihz "tail -30 /var/log/dsh-web.log"

# ── 改配置（热生效，不用重启；但代码改动必须重启）──
T=$(ssh alihz "cat /opt/qq-bridge/state/console-token")
# 只读
ssh alihz "curl -s -H 'x-console-token: $T' http://127.0.0.1:3100/api/socialV2/config"
# 写（示例：改群聊唤醒上限）
ssh alihz "curl -s -X POST -H 'x-console-token: $T' -H 'content-type: application/json' \
  -d '{\"wake\":{\"maxWakePerHourInGroup\":20}}' http://127.0.0.1:3100/api/socialV2/config"

# ── 隧道 ──
ssh -L 3081:127.0.0.1:3081 alihz -N   # DSH 界面
ssh -L 6081:127.0.0.1:6081 alihz -N   # 空间扫码(VNC)
```

### ⚠️ 操作铁律（都是踩出来的）

1. **改代码必须 `systemctl restart qq-bridge`** —— 桥接不热重载代码
2. **改 config 走控制台接口会落盘**；直接改 state 文件**不会**被运行进程读到，需重启
3. **`qq_send_sticker` 传 id 不传 desc** —— 她曾拿 desc 当 id 试发失败（会占用一轮工具调用）
4. **给网关传图用 `base64://`**，别用 `file://`
5. **reserved2 的 POST 必须带 `x-agent-token`**

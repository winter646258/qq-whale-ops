## 4. 这轮踩的坑（按痛感排序，都值得记住）

### 4.1 万能桩会吞掉真实作用域错误
写了一个用 Proxy 兜住所有未声明标识符的验证 harness，`bounded` 被喂成桩函数，于是**测试全绿、线上每轮唤醒都抛 `bounded is not defined`**。
真相：`bounded` 是 `buildWakeSnapshotV2` 内部的**局部箭头函数**，而调用它的 `buildSharedMemoryLineFor` 在模块层，作用域根本不通。
**教训**：验证要用「括号配对抽真实函数 + 真数据」的 harness，不要用万能桩。

### 4.2 语法花括号配平 ≠ 语义没坏
补丁把 `if (reason === 'poke') {` 复制成两层，`node --check` 照样通过 —— 外层 if 把 poke 分支和最后的通用 `return` 全包进去，**任何非 poke 的 reason 都返回 undefined**。
发现方式：抽函数看长度，88358 字符（正常 11816）。
**教训**：带锚点插入必须断言锚点唯一性（`ensure(SRC.count(anchor) == 1)`）。

### 4.3 `apply(before=False)` 是替换语义
`SRC.replace(anchor, addition, 1)` 会把锚点整行换掉，所以 `addition` 必须自己把锚点行原样放回。
更狠的一层：`IMPORT_ANCHOR = "} from './xxx-store.js';"` 是 import 的**收尾行**，把新 import 写它前面等于往未闭合的大括号里塞 `import` 语句。
**正确顺序：先锚点行，再新 import。**

### 4.4 `node --check` 在 /tmp 下什么都不检查
无 `package.json` 时 Node 按 CJS 解析 `.js`，对含 `import` 的文件**直接返回 0**。
必须 `printf '{"type":"module"}' > package.json`。

### 4.5 `grep -c` 数的是行数不是次数
HTML 是一整行，`grep -c "b_algo"` 返回 1，实际出现 10 次。差点误判搜索解析器坏了。

### 4.6 日志没有日期，只看 `HH:MM:SS` 会跨天串台
`/var/log/qqbridge.log` append 不 rotate，`10:33:18` 可能是昨天的。曾把 10-21 的 `sessionController is unavailable` 当成今天的新故障。
**必须按「桥接已启动」行号分段定位。**

### 4.7 补丁「已装，跳过」是死结
文件里装了旧内容（带 `rawPath`），补丁因 MARKER 命中而跳过 → 永远修不好。
解法：**手工修线上文件**，再让补丁补上。

### 4.8 回滚备份不能跨修复版本
拿 `bridge.js.bak-phone-...-120710`（早于 rawPath 修复）回滚，会把已修的 `rawPath` 又带回来。

### 4.9 MARKER 不能有前缀关系
`imgapprove-tool` 是 `imgapprove-tool-desc` 的子串 → 第二处被误判「已装」跳过。

### 4.10 生产重启会打断长任务
12:22 那三次「生图请求」全无结果，不是 bug——是我 12:23:44 重启服务，36 秒的生图被 SIGTERM 掐断。
**教训**：重启前先看有没有正在跑的长任务（生图 36~50 秒、黑话研究最长 12 分钟）。

### 4.11 部署插件的正确姿势
`dsh plugin add` 期间，DSH 的 host 侧 HMR **默认开着**，会重排插件树。`dsh-native-memory` 的 patch 整体替换了 `session-query-sqlite` 配置，而 `sessionController` 的 inject 里有 `sessionQuery` → 整条依赖链断掉，`session/follow` 每 3 秒报 `service-unavailable`，**刷了 1660 条，挂了 83 分钟**。
**铁律：以后装插件先 `systemctl stop qq-dsh`，改完再 start。**

### 4.12 装包本身不是运行时风险，是「下一次重启」的风险
「装完不重启就不生效」这个判断是错的——`package.json` 的 bundles 列表在进程内被 HMR 读到时就已经改了。

## 5. 关键机制备忘（改代码的人需要知道）

### 5.1 生图闸门有三层，别搞混

```
① deliverPromptNow 开头 → 无条件写 __qqTurnContext + 打「授予额度」日志（**只是日志，不是判定**）
② /api/socialV2/image   → imageAllowedNow() 真判定（回合上下文 / 宽限 / scene）
③ imageSceneFor         → owner-private（主人私聊）/ owner-group（群 + 120s 内主人发言 + byMention）
```

**「授予额度」日志骗过我一次**：拿它统计「给了 74 次额度、0 次请求」是错的，那只是回合数。

群聊的 `byMention` 兜底：reason 判不出时，看「主人 3 分钟内在群里说过话」——冒充挡不住 `isOwner`（按 QQ 号），改昵称无效。

### 5.2 对话上下文是「跟着回合走」的
`turn/end` 时清空 `__qqTurnContext`，同时记 `__qqTurnContextEnded`（**reason 必须一起存**，宽限分支要拿它判 `byMention`）。
群聊额外放宽：回合已结束但 `imageSceneFor` 仍成立，就放行（生图要 36 秒，她常常下一轮才调工具）。

### 5.3 共享记忆的可见性是「按群点名」
`visibleGroups: string[]` 而不是 `groupVisible: boolean`。
理由：A 群的梗搬到 B 群，B 群的人根本没有那个上下文，**那不是共享记忆，是串台**。
`owner_private` 即使被误传 `visibleGroups` 也会在构造时清空。

### 5.4 好感度绝不回退到全局
`getAffinity` 没存过就是 `null`。老格式那份全局值是「最后在哪说的就归谁」，拿它当所有人默认值正是要消灭的串台。

### 5.5 主动报告只能往更保守的方向调
`minIntervalMs = Math.max(6h, want)`、`maxPerDay = Math.min(4, want)`。
暂停的双条件：`unansweredStreak >= 3` **且** 距 `max(lastOwnerReplyAt, createdAt) >= 3天` —— 否则主人天天聊天只是没接这个话题也会被停一周。

### 5.6 两条 agent token 路径
- 控制台端点：`x-console-token`（`state/console-token`，48 字符）
- 会话端点：`x-agent-token`（每个会话一把，`state/social-v2.json` 的 `agentToken`）
- 浏览器桥：`x-phone-token`（`state/phone-token`，49 字节，懒生成）
- **`agentTokenOk` 全文件 46 处调用**，改它等于全局放开；只给 4 个发送端点 + `/api/send/*` 换成 `agentTokenOkOrOwnerDelegate`

> **别相信「日志说成功」。**

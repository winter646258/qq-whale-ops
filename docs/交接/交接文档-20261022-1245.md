## 0. 一句话说明这是什么

一个住在 QQ 里的 AI 角色「八千代」（自称小鲸鱼/鲸鱼娘），跑在阿里云一台 2G 小机器上。
她有自己的记忆、情绪、日程、黑话库、表情包，会主动找人说话，也会画图。

她的「大脑」不是某个模型，而是一个本地 DSH（DeepSeek Harness）进程；某个渠道的模型额度用完，
旁边的守护脚本会自动把她换到下一个免费渠道上，她本人和群友都察觉不到。

## 1. 架构

```
QQ 群 / 私聊
   │
   ▼
QQ 小号 2157801858
   │  （QQ 协议）
   ▼
SnowLuma 网关（Docker，宿主端口 127.0.0.1:3000 HTTP / 3001 WebSocket）
   │  （OneBot v11）
   ▼
qq-bridge  ←→  /opt/qq-bridge/src/bridge.js（12701 行，进程常驻，端口 3100 控制台）
   │
   │  DSH HTTP API（127.0.0.1:3081）
   ▼
DSH（DeepSeek Harness 0.2.0-rc.2，/root/.dsh，端口 3081）
   │
   ├── MCP 子进程 mcp-snowluma-safe.js   （45 个 qq_* 工具）
   ├── MCP 子进程 mcp-host-server.js     （宿主机能力）
   └── MCP 子进程 mcp-web-search-safe.js （联网搜索/抓网页）
   │
   ▼
模型渠道（loomy / trae / raccoon / …，由 qq-provider-switch 守护选择）
```

**数据流要点**

1. 群里有动静 → bridge 判断要不要唤醒她（触发条件见 §6.3）→ 拼一段 prompt 投给 DSH。
2. DSH 用当前渠道的模型跑一轮，模型通过 MCP 工具发消息、查记录、读写记忆。
3. bridge 把模型产出的消息按节奏拆条发回 QQ（分条、间隔、长短停顿都由 bridge 控制，不是模型自由发挥）。

## 2. 服务器与服务

**服务器**：阿里云 `alihz` / `121.40.52.115`，工作目录 `/opt/qq-bridge`。

| systemd 服务 | 端口 | 作用 |
|---|---|---|
| `qq-dsh` | 3081 | DSH 本体。`ExecStart=/usr/bin/dsh --profile web --no-open --host 127.0.0.1 --port 3081`，`DSH_HOME=/root/.dsh`，`WorkingDirectory=/root` |
| `qq-bridge` | 3100（控制台） | 桥接主程序 `src/bridge.js` |
| `qq-provider-switch` | — | 渠道守护，每 60 秒检查一次（见 §7） |
| `qq-zone-watch` | — | QQ 空间巡检（点赞/评论） |

**SnowLuma 不是 systemd 服务**，是 Docker 容器，3000/3001 由 docker-proxy 监听。

**资源现状（2026-10-22）**：内存 total 1736MB / used ~950MB / available ~600MB；swap 已用 727MB。
swap 大户是 QQ 客户端（约 440MB，含 zygote）和 SnowLuma（约 190MB），**DSH 与 bridge 没被换出**。
磁盘 40G / 用 14G（36%）。

> ⚠️ 这台机器只有约 600MB 可用内存。任何「再加一个常驻进程」的想法都要先算这笔账。
> `qq-dsh` 的 unit 里写着 `MemoryHigh=768M`、`OOMScoreAdjust=200`。

顶层键与要点（**凭据已隐去**）：

**配置写入纪律**

- 改 `config.json` 前必须备份（现有命名习惯 `config.json.bak-YYYYMMDD-HHMM`）。

- `setup-dsh.mjs` 会**整体重写** `cordis.patch.yml` 里 `# === qq-bridge MCP BEGIN/END ===` 区块，手改那块会被覆盖。

### 5.2 `src/mcp-snowluma-safe.js`（1495 行，45 个工具）

`TOOL_CONFIG_FLAGS` 表（约 231 行）把「工具名 → `cfg.socialV2.tools` 开关」映射起来；
每个工具用 `server.tool(name, 描述, zodSchema, handler)` 注册，handler 统一 `agentApi(...)` + `serializeModelData(data)`。

**注意**：handler 只把结果**当文本**回给模型。图片类工具（`qq_generate_image`）因此**必须由 bridge 侧负责发送**，
否则模型只拿到一个路径，主人什么都收不到（这个坑踩过一次，见 §11）。

### 5.3 四个 store（纯逻辑 ESM，可单测）

| 模块 | 数据文件 | 要点 |
|---|---|---|
| `diary-store.js` | `diary.jsonl` | `MAX_ENTRIES=2000`、`MAX_TEXT_CHARS=200`、`MAX_MOOD_CHARS=20`；**单层，无衰减**（设计上留白） |
| `portrait-store.js` | `portrait.json` | facet `doing/view/bond`，`weight` 1–9 表示「这条印象对她多重要」，**不是好感度**；注释明写「不自动涨不自动跌」 |
| `schedule-store.js` | `schedule.json` | 时段 `上午/下午/晚上`，`MAX_ENTRIES=300`，`REVIEW_START_HOUR=4` |
| `mood-store.js` | `情绪.json` | PAD 三维 + 暗流 + 好感度 1–10。**惰性衰减**（读时按 `now - updatedAt` 现算），无定时器 |

`mood-store.js` 的核心公式：

```
v(t) = baseline + (v0 - baseline) * 0.5^(Δt / halfLife)
```

半衰期按偏离底色的幅度分三档：>0.6 用 90 分钟、0.3–0.6 用 45 分钟、<0.3 用 20 分钟。
它有 125 条单测，跑法：`node src/mood-store.test.mjs`。

## 7. 渠道与降级（最容易出事的部分）

### 7.1 候选链

```bash
CHAIN_PROVIDERS=(loomy trae raccoon)
CHAIN_MODELS=(DeepSeek-V4.1-Flash deepseek-v4.1-flash sn-deepseek-v4-1-flash)
CHAIN_EFFORTS=(low light on)
```

**快而贵在前，慢而省在后**。三者都免费。

### 7.2 守护怎么判断

两个判据，任一成立就降到下一级：

1. **故障**：`FAIL_PATTERN` 在最近 `WINDOW_SEC=600` 秒内命中 `FAIL_THRESHOLD=3` 次
2. **慢**：从 `token-ledger.json` 读**当日累计增量**（本次 `ttftSumMs/ttftCount` 减上次快照），
   平均首字 > `SLOW_TTFT_MS=15000` 且样本 ≥ `SLOW_MIN_SAMPLES=3`，连续 `SLOW_STRIKES=2` 次

**为什么用增量而不是当日均值**：当日均值会被切换前的历史稀释，越晚越迟钝。

**冷却**：`SWITCH_COOLDOWN_SEC=180`。**恢复探测**：兜底期间每 `RECOVER_PROBE_INTERVAL=300` 秒探一次主渠道，
能用就切回。

### 7.3 2026-10-22 实战记录

```
08:04:27 loomy -> trae  main-failed
08:05:49 trae -> loomy  recovered
08:52:21 loomy -> trae  main-failed
08:58:56 trae -> loomy  recovered
09:35:24 loomy -> trae  main-failed   ← 停在 trae
```

原因是 loomy 积分余额不足（`09:33:01 loomy: 积分余额不足，请获取积分后再试`）。
**这不是故障，是设计行为**。loomy 充上分后守护会自动切回。

> 每次切换都会 `systemctl restart qq-bridge`，所以日志里「桥接已启动」出现多次且 `NRestarts` 始终 0 是正常的。

## 8. 补丁机制（最重要的开发纪律）

`bridge.js` 有 12700 行，**不允许手改**。所有改动走 `patches/*.py`：

```python
def sub(text, old, new, label):
    n = text.count(old)
    if n != 1:
        print(f'❌ {label}：命中 {n} 处（要求恰好 1 处），不写盘')
        sys.exit(1)
    return text.replace(old, new, 1)
```

**规矩**

1. 每处替换必须断言命中**恰好 1 次**，任何一处对不上就**整份不写盘**。
2. 写完 `node --check src/bridge.js`。
3. 备份命名 `src/bridge.js.bak-YYYYMMDD-HHMM`。
4. 部署：`systemctl restart qq-bridge`，然后验活（MainPID / NRestarts / 日志）。
5. 补丁脚本**提交进仓库**（它就是这个项目的版本历史）。

**当前补丁清单（38 个）**：见 `patches/` 目录。最近五个：

| 补丁 | 作用 |
|---|---|
| `patch-mood-system.py` | 情绪系统接线（bridge 7 处 + MCP 2 处） |
| `patch-turn-gate.py` | 生图闸门从固定 120 秒改为跟着回合走 |
| `patch-image-send.py` | `onebotSend` 支持图片段 + 生图后自动发送 |
| `patch-provider-chain.py` | 守护从「主+兜底」改成三级候选链 |
| `patch-tmp-workspace-dir.py` | 探测/测速不再每次新建 `/tmp` 会话目录 |

## 11. 事故史与教训

### 11.1 2026-10-21 18:32 · 装插件把 DSH 打挂 83 分钟

`dsh-native-memory` 的 bundle patch 改写了 `session-query-sqlite` 配置，云上 DSH 是 0.2.0-rc.2，
`sessionController` 起不来，日志刷出 **1660 条** `gateway/service-unavailable`。
`systemctl` 全程显示 active —— **进程活着，内部服务死了**。

**教训**：只看 `is-active` 查不出这种故障；装带 bundle 的插件要当成上线操作对待。

### 11.2 2026-10-21 · `turnContext is not defined`

补丁把 `let turnContext = null` 插在配置区，而使用它的函数在另一个闭包里，
`node --check` 通过、运行时报 22 条 `补投异常 group:906710082: turnContext is not defined`。

**教训**：`node --check` 只查语法，不查作用域。跨函数共享的模块状态要挂 `globalThis` 或声明在最外层。

### 11.3 2026-10-22 · 「token 花了但图发不出来」

`qq_generate_image` 只把路径当文本回给模型，而 `onebotSend` 只构造文本段 ——
**整条出站路径没有图片能力**。她画了 5 张，主人一张没收到。

**教训**：工具「返回成功」不等于「用户收到」。端到端验证要看最终那份产物落在谁手里。

### 11.4 2026-10-22 · 误把昨天的故障当今天的

日志只有 `HH:MM:SS` 没有日期，`07:38 buddy 请求被拦截` 被当成当天新故障排查了半天，
实际是 10-21 早上渠道链还是 buddy 时代的旧记录。

**教训**：这个日志文件跨天，判断「是不是现在」必须同时看行号位置和相邻行的时间。

### 11.5 通用教训

- **文档里写「某功能已上线」≠「某功能跑通过」**。判断依据必须是日志里那条成功路径的实际输出行。
- **单次探测不足以判定渠道快慢**（同样 loomy，一次 1.7 秒一次 10.4 秒），要看 ledger 的累计增量。
- **不要依赖 `scp`**：深夜频繁 `Connection timed out`，改用 base64 走 ssh 最稳。
- **PowerShell 不支持 heredoc**，`git commit -F - <<EOF` 会报错，要写文件再 `git commit -F <file>`。

## 13. 交接者需要先知道的十件事

1. **`bridge.js` 不手改**，一切走 `patches/*.py` + 命中数断言。
2. **改完必须 `node --check`，然后 restart，然后看日志**。三步缺一不可。
3. **`/var/log/qqbridge.log` 跨天**，只有 `HH:MM:SS`，判断时间要看行号位置。
4. **服务 active ≠ 服务健康**。DSH 内部服务挂了进程照样活着。
5. **渠道会自动切换**，`config.json` 里的 provider 随时可能被守护改掉，别拿它当唯一真相。
6. **重启 bridge 很正常** —— 守护切渠道就会重启，`NRestarts=0` 说明不是崩溃。
7. **凭据都在 `config.json`（mode 600）**，不要打印、不要提交、不要贴进对话。
8. **生图花钱**（$0.01/张），测试时注意余额。
9. **这台机器只有 600MB 可用内存**，加任何常驻进程前先算账。
10. **SSH 用 `C:\Windows\System32\OpenSSH\ssh.exe`**（Git 自带的那份会崩 Win32 error 5）。

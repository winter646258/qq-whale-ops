## 一、为什么换

原来：`diary/日记.md`，每行 `- [YYYY-MM-DD HH:mm] 正文`。

### 问题 1：结构不牢（最致命）

正文里的换行被压成空格，但**正文若以 `- ` 开头，读取时会被误认成新日记**。

实测对照：
- 旧 Markdown 方案：写一条 `- 今天买梨了\n- 但没给她留` + 一条普通日记 ⇒ **会被读成 4 条**
- 新 jsonl：**还是 2 条**，内容完整保留

`diary-store.test.mjs` 里专门有一节叫「结构健壮性：正文里的 "- " 不会破坏它（Markdown 方案会）」守这个。

### 问题 2：时间戳是 UTC（差 8 小时）

```js
const stamp = new Date().toISOString().slice(0, 16).replace('T', ' ');
```

服务器时区 `Asia/Shanghai`，`toISOString` 返回 UTC。实测 22:24 会写成 **14:24** ——
她深夜写的日记会显示成下午。

> 讽刺的是，`bridge.js` 里早有正确的 `localClock()`（1151 行），注释还写着
> 「此前用的是 toISOString()，写进日志的是 UTC，和本地时间差 8 小时」。
> 日志那边修过，日记这边漏了。

**实测修复后**：`[2026-10-20 22:32]` ✅（不是 `14:32`）

### 问题 3：没有情绪字段

这张「人体系统」图里唯一整块空白的是**「情绪系统：心情有状态、有原因、有时长」**。
日记是她唯一能自然记录情绪的地方 —— 这是最便宜的人口。

## 二、换成什么

`diary/日记.jsonl`，一行一条：

```json
{"id":"d479ea","t":1792506859407,"time":"2026-10-20 22:34","day":"2026-10-20","mood":"有点懊恼","text":"- 买梨了 - 但没给她留"}
```

| 字段 | 用途 |
|---|---|
| `id` | 改写时定位（`qq_diary` 现在支持按 id 或按正文片段改） |
| `t` | 机器用的时间戳，排序用 |
| `time` / `day` | 给人看的本地时间 |
| `mood` | 心情，**可选** |
| `text` | 正文，单行 |
| `editedAt` | 改写过才有 |

### 关于 mood 的三个刻意选择

1. **不设枚举** —— 让她随便写，系统不分类、不统计情绪分布。
   一旦做成固定几档（开心/难过/平静），她就会开始"贴标签"而不是"记事"。
2. **可选，不硬凑** —— 工具描述写的是「不想标就不传，别硬凑」。
   每条都带个假心情比没有更糟。
3. **不进注入** —— 目前不往唤醒提示词里塞「你昨天心情如何」。
   先让她记，观察她会不会自然用；用得上再加。

## 三、为什么没有 originalText（和「印象」不同）

记忆系统的原则是「模糊是改写，不是删除」，所以印象改口时会留底。

**日记不留底。** 人会重读自己写的东西然后改口，这是日记的正常行为。
把每条改动都留底，反而像在审问她。

所以 `updateDiaryEntry` 里**没有** `originalText` 字段，且测试里有一条断言守这个：
`ok('没有 originalText（日记不留底，和印象不同）', a.originalText === undefined)`

## 四、兼容与迁移

- 旧的 `diary/日记.md` **保留**（只读），另有 `.bak-<时间戳>` 备份
- 新增 `POST /api/socialV2/diary/migrate`（**仅控制台**，不带 agent token 的角色调不到）
- **幂等**：目标 jsonl 已有内容就跳过，不覆盖
- 迁移时**保留原文时间戳，不纠时区** —— 历史数据不该假装精确

实测：
```json
{"ok": true, "skipped": true, "reason": "目标 jsonl 已有内容，不覆盖", "total": 1}
```

## 五、容量与安全

| 项 | 值 | 说明 |
|---|---|---|
| 条数上限 | 2000 | 从 500 放宽（jsonl 更紧凑） |
| 字节上限 | 2 MB | 从 64 KB 放宽 |
| 单条正文 | 200 字 | 不变 |
| 心情 | 20 字 | 新 |
| 限流 | 3 次/分、20 次/时 | 不变 |
| 敏感信息 | `SENSITIVE_RE` 拦截 | 正文与心情都查 |
| 文件权限 | `600` | 实测确认 |

**只读降级闸**：读失败 ⇒ 置 `diaryWritable=false` ⇒ 拒绝写入。
这条是照 slang/sticker 的教训来的：**绝不能把"读不动"当成"空日记"再写回去**，
那会把整本日记清空。

### 中途一次"假 bug"

验证时出现过一次 `total` 不增长，咱一度以为是写入失败。
实际是**限流在正常工作**（3 次/分钟），咱连续写了 4 次。
等 65 秒后重试就成功了。

> **教训：验证失败时先怀疑自己的调用节奏，再怀疑代码。**
> 这和交接文档里那句「报失败时先怀疑判定逻辑，再动生产代码」是同一个道理。

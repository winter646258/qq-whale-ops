## 1. 本次做了什么

### 1.1 情绪系统（新增能力，两步）

新文件 `src/mood-store.js`（538 行，纯逻辑）+ `src/mood-store.test.mjs`（**125 通过 0 失败**）。

**设计上的四个取舍**，都是踩过坑之后定的：

1. **不做每分钟 tick，做惰性衰减。** 指数衰减有半群性质
   （`decay(decay(v,t1),t2) === decay(v,t1+t2)`，单测有专门用例），
   读时按 `now - updatedAt` 现算与每分钟 tick 数学等价。
   云上只剩 568MB 可用、bridge 已挂 6 个 `setInterval`，不能再加节拍器。
2. **数值归数值，标签归标签。** PAD 三点只负责衰减和阈值；情绪标签她自由写，
   不设枚举 —— 沿用 `diary-store.js` 那句注释的道理：一旦写成固定几档，
   她就会开始贴标签而不是记事。
3. **不自动打分。** 没有「这句话让她生气 → pleasure -0.2」这种文本判断。
   情绪只有两个来源：她自己写、时间。
4. **底色不做自动漂移。** 原本写了 `driftBaseline`，被单测证伪：
   它需要一个「最近的长期情绪」当输入，而模块只存得住「最后一次写入的心情」——
   拿瞬时值当长期平均，等于让一个下午的心情改写性格；按时间衰减再取又推不动
   （24 小时后 0.9 早就代谢归位）。改成显式 `setBaseline`（一次最多挪 0.05），
   和好感度同一个逻辑：**系统不猜她变成了什么样，她自己觉得变了再调。**

**半衰期按偏离幅度分档**：`>0.6` 用 90 分钟、`0.3~0.6` 用 45 分钟、`<0.3` 用 20 分钟。

**线上接线**（`patches/patch-mood-system.py`，bridge.js 7 处 + mcp-snowluma-safe.js 2 处）：
- `cfg.socialV2.mood` 开关；`moodStore()` **故意不缓存**（缓存就拿旧值算衰减；文件几百字节）
- 注入 `moodLine`，插在 `statusLine` 之后 `wakeLine` 之前
- 路由 `/api/socialV2/mood`（GET/POST），六个 action：
  `read`（返回 `view` + `stats` + 带 id 的 `undercurrent` + `affinityNote`）、
  `set`、`vent`、`resolve`、`affinity`、`baseline`
- 工具 `qq_mood` 已注册（`qq_get_prompt` 清单 + MCP `TOOL_CONFIG_FLAGS` + `server.tool`）

**已验证**：六个 action 全部工作，落盘 `/opt/qq-bridge/state/情绪.json`。
`set` → `【此刻】有点累 · 摆弄插件摆到半夜（刚刚）`；
`vent` weight 0.6 → 多一行 `【压着】1 件事没说`（阈值 `UNDERCURRENT_ALERT = 1.5`，
未达阈值措辞是「没说」而不是「压得沉」）。

**未验证**：注入在**真实 QQ 唤醒**里长什么样。
（用 `notify-ai` 试过，但那条路径自己拼 prompt、不走 `buildWakePromptV2`，
所以测不到 —— 详见 §6 教训。）

### 1.2 生图（新增能力，已端到端验收）

**$0.01/张，1024x1024，约 48 秒，返回 b64 + url。**

补丁 `patches/patch-image-gen.py`。核心是**权限闸门**，主人要求「只有管理员指定
或与管理员的私聊（自动唤醒时）」才允许：

- `deliverPromptNow` 每轮开头记 `globalThis.__qqTurnContext = { key, reason, at }`
- `imageSceneFor(key, reason)`：`private:<ownerQQ>` → `owner-private`；
  群里且该群最近 120 秒有 `isOwner` 消息且 reason ∈ `atMention|nameMention|question`
  → `owner-group`；否则 null
- `imageAllowedNow(key)`：turnContext 存在 + 未超 120 秒 + key 一致 + 场景非空

**实测三种场景**：

| 场景 | 结果 |

| 主人私聊、对话中 | ✅ 通过（`scene: owner-private`） |
| 群里（当前轮次是私聊） | ❌ 「这个会话不是当前正在进行的那个」 |
| 冒充别的私聊号 | ❌ 同上拒绝 |

### 1.4 windking 中转站 404 根因

**根因**：`dsh-our-free-model` 的 `src/adapter.js` 把 catalog 的带前缀 id
（`deepseek/deepseek-v4.1-flash`）**原样塞进请求体的 model 字段**发给上游。
聚合渠道的上游是别人的网关，没有我们的 provider 命名空间，只认裸名
`deepseek-v4.1-flash`，于是回 404 `model not found`。

**修法**（`patches/patch-ofm-aggregate-model.py`）：
```js
const wireModel = aggregate ? entry.modelId : entry.id
const payload = buildPayload(wire, wireModel, input, options, ceiling, resolveImage, sink)
```
只对 aggregate 渠道拆前缀 —— EAC 的 `deepseek-ai/...` 是上游自己的模型名，拆了反而错。

**修完实测三次全过**：10,288ms / 12,856ms / 24,590ms。

## 6. 本次踩的坑（教训）

1. **`node --check` 通过 ≠ 作用域正确。**
   生图第一版把 `let turnContext = null;` 插在配置加载区，而用它的
   `deliverPromptNow` 在另一个函数闭包里 —— 语法没问题，运行时刷 22 条
   `turnContext is not defined`。跨函数共享的模块状态要么挂 `globalThis`、
   要么声明在最外层。

2. **「装完不重启就不生效」是错的。**
   `dsh plugin add` 那一刻就会冲击在跑的进程：8 月 21 日 18:32 装
   `dsh-native-memory` 直接把 `sessionController` 搞挂 83 分钟、1660 条报错。
   而且 `systemctl is-active` 全程显示 active —— 进程活着，内部服务死了。
   **只看 `is-active` 查不出来**，要看日志。

3. **验证要挑对通道。**
   想验「情绪注入有没有生效」，用 `notify-ai` 触发了唤醒，日志也显示发送了，
   但解压会话文件 `grep "【此刻】"` = 0 —— 因为 `notify-ai` 自己拼 prompt、
   根本不走 `buildWakePromptV2`。**测一条路径，得先确认你测的是那条路径。**

4. **工具没人用，先怀疑说明书。**
   `web_search` 一直可用且没报错，但调用次数是 0。工具描述里的自我设限
   （「仅用于理解词义」）比任何技术缺陷都更能让一个功能等于不存在。

## 7. 操作纪律（沿用，勿忘）

- SSH 必须用 `C:\Windows\System32\OpenSSH\ssh.exe`（Git 自带的会崩 Win32 error 5）
- `C:\Windows\System32\scp.exe` **不存在**，正确路径是 `C:\Windows\System32\OpenSSH\scp.exe`
- 深夜 scp 常 timeout，**用 base64 走 ssh 最稳**：
  `$b64=[Convert]::ToBase64String([IO.File]::ReadAllBytes($p)); ssh alihz "echo '$b64' | base64 -d > /tmp/x"`
- SSH 偶发 timeout，**重试 3~4 次**
- 改文件流程：备份 → 补丁脚本（精确串替换 + **命中数断言**，不符不写盘）→
  `node --check` → 隔离测试 → 部署 → `systemctl restart` → 验活
- PowerShell 会本地展开 `$(...)`，复杂远程命令用单引号包裹或写成文件传上去
